# 术语对照：计算机词 → 法学人听得懂的话

> 法学背景、看不懂本文档里的技术词？先看这一页。**大多数词你根本不用懂**——文档里出现它们，只是因为你可能会在文件里看到。

## A. 你会亲手用到的（必须懂）

| 词 | 法学人版解释 | 你要做什么 |
|---|---|---|
| **命令行 / 终端 / PowerShell** | 一个「跟电脑说话」的窗口：你打字下命令，电脑执行。不是你写论文的 Word。 | Windows 按 `Win+R` 输入 `powershell` 回车；macOS 打开「终端」 |
| **命令** | 一行要电脑做的事，比如「把文件下载下来」。 | 复制、粘贴、回车 |
| **参数** | 命令后面带的「附加要求」，一般以 `--` 开头。例如 `--pdf 论文.pdf` 意思是「我要处理这个 PDF」。 | 把文件名换成你自己的 |
| **文件夹 / 目录 / 路径** | 电脑里文件存放的位置。`~` 表示「你的用户文件夹」（Windows 是 `C:\Users\你的用户名`）。 | 知道结果在哪个文件夹就行 |
| **cd** | 打开某个文件夹。 | 照抄 |
| **git clone** | 从网上下载一份完整的项目到本地。 | 照抄 |
| **pip install** | 安装运行所需的「库」（见 D 组）。 | 照抄 |
| **pandoc** | 一个把 Markdown 转成 Word 的小工具（脚注靠它）。 | 装一次即可 |

## B. 你会看到但不用懂的文件

| 词 | 解释 |
|---|---|
| **.py** | Python 脚本文件——技能的程序代码，你不需要改 |
| **.md** | Markdown 文档——纯文本排版文件，用记事本也能打开 |
| **.json** | 一种「结构化数据」文件，长得像 `{"标题": "……", "节点": [...]}`，程序靠它读写数据 |
| **.docx / .pdf** | Word 文档 / PDF 文件，你天天用 |
| **.txt** | 纯文本文件 |
| **README.md** | 项目说明书（就是本文档） |
| **SKILL.md** | 技能的定义文件：告诉 AI 这个技能叫什么、什么时候用、怎么用 |

## C. 文档里出现的流程词

| 词 | 法学人版解释 |
|---|---|
| **pipeline（流水线）** | 一条自动流水线：PDF → 拆段落 → 提取引注 → 画论证图 → 出 Word 报告，一次跑完，不用你一步步点 |
| **脚本（script）** | 一段替你干活的程序，比如 `pipeline.py` 就是流水线脚本 |
| **运行** | 让电脑执行某个脚本（就是我们说的「跑一下」） |
| **输出 / 产出** | 跑完之后生成的文件（报告、图、数据包） |
| **校验器（validator）** | 一个「检查员」程序：检查论证图有没有照抄原文、有没有把别人观点记到作者头上、有没有孤立节点 |
| **测试（test）** | 给程序做的「体检题」，确保改代码后没把功能改坏 |
| **提示词（prompt）** | 你给 AI 的指令文本，比如「请精读这一章」——读透包里的 `.prompt.md` 就是提示词 |
| **输出槽** | 提示词文件末尾留的空位，把 AI 的回答贴进去，就完成这一轮 |

## D. 装的东西是什么（一次性）

| 词 | 法学人版解释 |
|---|---|
| **Python** | 一种编程语言，本技能用它写程序。你电脑上可能已装；装它像装一个 App |
| **依赖 / 库** | 程序需要提前装好的「零件包」。比如 `PyMuPDF` 负责读 PDF、`python-docx` 负责读写 Word |
| **matplotlib / networkx** | 画图用的两个库（画论证图） |
| **pandoc** | 把 Markdown 转成 Word 的转换器 |

## E. 论证图里的「法学概念」（这个必须懂）

| 词 | 解释 |
|---|---|
| **claim graph（论证图 / 论证结构图）** | 把一篇论文的论证拆成「节点 + 箭头」的图。节点=一句话命题；箭头=命题间的关系 |
| **节点（node）** | 一条「可以判断真假」的命题，分类型：问题、前提、中心命题、证据、反方、文献、规范结论 |
| **边 / 箭头（edge）** | 两个命题之间的关系，并注明理由（warrant） |
| **warrant（理由）** | 这条箭头为什么成立——不是写「支持」，而是写「为什么能推出」 |
| **quote（原文引用）** | 从论文里逐字摘的句子，用于核对 |
| **text（概括）** | 拆解者用自己的话概括的命题（不能照抄原文） |
| **cite_id（引注）** | 这条命题的出处：`cite_self` = 本文；`ref-…` = 被引者的文献 |
| **归属铁律** | 反方/文献（别人的观点）必须记在别人名下，不能挂 `cite_self` 冒充作者观点 |
| **diagnosis（诊断标记）** | 标记论证的弱点：孤立、证据不足、跳步、断裂 |

## F. 你可以完全忽略的

- **API、token、仓库（repo）、commit、push**：这些是程序之间的事，你只在「上传/同步代码」时用一次，平时不用碰；
- **正则（regex）、schema、JSON 字段名**：程序内部细节，你不需要看懂；
- **单元测试、五维审稿测试**：给程序做的检查，你只需要知道「全过」就行。
